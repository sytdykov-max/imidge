# Архитектура нового Imidge

## 1) Технологический стек

- Backend: Medusa 2 (Node.js, TypeScript)
- Frontend: Next.js (App Router, SSR/ISR)
- БД: PostgreSQL (новый контур), Redis (кеш/очереди)
- Поиск: стартово встроенный фильтр, затем Meilisearch/Typesense (опционально)
- Хранилище медиа: S3-совместимое (локально можно filesystem)

## 2) Контуры системы

### Storefront (apps/storefront)

- Отвечает за SEO-страницы, UX, рендер каталога и checkout-flow.
- Хранит только UI-состояние, не дублирует бизнес-логику заказов.
- Работает через API Medusa.

### Commerce Backend (apps/medusa)

- Каталог/варианты/SKU/цены/скидки/заказы/клиенты.
- Админ-операции и интеграции доставки/оплаты.
- Единый источник истины по ecommerce-данным.

### Shared UI (packages/ui)

- Компоненты дизайн-системы из `new_site_imidge/dark`.
- Токены, базовые компоненты, шаблоны секций.

## 3) Принципы миграции со старого сайта

- Битрикс-копия только источник данных: категории, товары, URL, мета, изображения.
- Исторические URL сохраняются через карту редиректов 301.
- Данные мигрируются ETL-скриптами с валидацией.

## 4) SEO-архитектура

- SSR для критичных страниц (главная, категории, карточка товара).
- Каноникал, robots, sitemap index, schema.org Product/Breadcrumb.
- 301 редиректы со старых URL на новые маршруты.

## 5) MVP-срез (первая итерация)

- Главная
- Каталог (листинг + фильтры)
- Карточка товара
- Корзина
- Checkout
- Блог (листинг + пост)

## 6) Риски и решения

- Риск: сложные фильтры и legacy URL.
  - Решение: сначала поддержать ключевые фильтры, затем расширить.
- Риск: расхождение данных при миграции.
  - Решение: сухой прогон импорта + отчёты сверки.
- Риск: внешние интеграции из legacy.
  - Решение: отдельный слой интеграций только на новом backend.

## 7) Definition of Done этапа архитектуры

- Утверждена структура репозитория и контуры.
- Зафиксирован MVP-срез.
- Зафиксированы правила SEO и миграции.
